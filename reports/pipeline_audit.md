# ASDMotion pipeline audit

Audit date: 2026-09-16. This is a **source-level audit with synthetic executable counterexamples**, not a completed reproduction of GPU training or the published evaluation. Ten counterexample tests pass: passing means that the documented upstream behavior was reproduced, not that upstream is correct. Run `.venv/Scripts/python.exe -m unittest discover -s tests -p test_upstream_semantics.py -v`. Evidence: [local test source](../tests/test_upstream_semantics.py).

## 1. Follow the information, not only the architecture

| Stage | Actual input → output | What it retains, removes, or assumes |
|---|---|---|
| OpenPose extraction | Video frames → BODY_25 x/y joint coordinates and confidence for each detected person | The source reads only `pose_keypoints_2d`; the downstream representation has no RGB texture, speech, objects, explicit depth, or finger landmarks. This is a representation inventory, not a claim that those other signals are unimportant. [ASDMotion, `openpose_executor.py:125–147`](../external/ASDMotion-main/src/asdmotion/pipeline/openpose_executor.py) |
| Joint conversion | BODY_25 → COCO-17 | Joint-name lookup gives source indices `[0,16,15,18,17,5,2,6,3,7,4,12,9,13,10,14,11]`. Neck, mid-hip, heel/toe joints disappear. [ASDMotion, `skeleton_layout.py:35–38,41–75,114–138`](../external/ASDMotion-main/src/asdmotion/pipeline/skeleton_layout.py) |
| Person slots | Per-frame skeletons → `[M,T,17,2]` and `[M,T,17]` score array | Up to five slots by default; every frame independently sorts people by average joint confidence. Slot index is not persistent identity. [ASDMotion, `openpose_executor.py:171–181`](../external/ASDMotion-main/src/asdmotion/pipeline/openpose_executor.py); [configuration:1–7](../external/ASDMotion-main/resources/configs/config.yaml) |
| Child selection | YOLOv5 class-1 boxes + pose boxes → per-frame child slot IDs | Maximum-IoU matching, prior-box continuity when multiple children, then nearby-frame recovery; this is not a learned temporal identity model. Default IoU threshold 0.01, confidence threshold 0.1, grace distance 20 frames. [ASDMotion, `skeleton_matcher.py:19–74`](../external/ASDMotion-main/src/asdmotion/child_detector/skeleton_matcher.py); [`child_detector.py:32–34`](../external/ASDMotion-main/src/asdmotion/child_detector/child_detector.py) |
| Sequence preparation | Long recording → overlapping pose windows | Defaults 200 frames, stride 30, minimum 60; at 30 fps these are about 6.67 s, 1 s, and 2 s. Tail windows are shorter. [ASDMotion, `splitter.py:8–37`](../external/ASDMotion-main/src/asdmotion/pipeline/splitter.py); [`preprocess.py:79`](../external/ASDMotion-main/src/asdmotion/detector/preprocess.py) |
| Child tensor and sampling | Per-person windows → one person → 48 sampled frames | Fork `ChildDetect` indexes one slot each frame. Fork training config first crops long sequences to 200 frames, then samples 48 frames. [MMAction fork, `pose_loading.py:699–707,15–131`](../references/source_snapshots/mmaction_pose_loading.py); [`augmentations.py:1961–1986`](../references/source_snapshots/mmaction_augmentations.py) |
| Heatmap representation | Coordinates/confidences → 17 spatial heatmap channels through time | Gaussian sigma 0.6, confidence controls amplitude, joint maps enabled and limb maps disabled. PoseCompact crops around pose; spatial resize/crop changes coordinate scale. Training uses 48×48 maps, validation/test 56×56. [MMAction fork, config pipelines](../references/source_snapshots/mmaction_asdmotion.py); [`pose_loading.py:407–450,583–619`](../references/source_snapshots/mmaction_pose_loading.py) |
| Recognizer | Heatmap volume → two class probabilities | ResNet3dSlowOnly depth 50, 17 input channels, three stages, I3D head, Kinetics-400 initialization. Test uses 10 temporal samples and their flipped counterparts, with probability averaging. [MMAction fork, config model/test pipeline/load_from](../references/source_snapshots/mmaction_asdmotion.py) |
| Temporal summary | Overlapping positive windows → events and duration/rate | The paper defines frame-wise maximum then threshold and contiguous-event union. The repository attempts union by grouping runs and merging overlapping positive runs; it has observable edge-case errors below. [Barami (2024/09), p.4](../references/papers/Barami2024_JAMA.pdf); [ASDMotion, `aggregator.py:5–64`](../external/ASDMotion-main/src/asdmotion/pipeline/aggregator.py) |

The 17-channel convolutional network is a **3D convolution over 2D heatmaps and time**, not a 3D human-pose estimator. Its confidence-weighted heatmaps can represent uncertainty in detected joint position/amplitude, but they do not make the resulting SMM score a calibrated clinical probability. The latter is an audit interpretation: the inspected configuration defines classification loss and probability averaging, without a calibration stage. [MMAction fork, model and `GeneratePoseTarget` configuration](../references/source_snapshots/mmaction_asdmotion.py).

## 2. What the algorithm is and is not trained to do

The paper trains a binary SMM detector within recordings of children already diagnosed with ASD. It does not establish ASD-versus-non-ASD diagnostic classification. The authors distinguish broad SMM detection from recognition of a few named action categories, and report generalization/onset-offset limitations. [Barami (2024/09), pp.3–4,9](../references/papers/Barami2024_JAMA.pdf).

**Interpretation for experimental design:** body-joint displacement, spatial configuration, bilateral coordination, and repeated movement are signals available to this representation. Fine finger articulation and interaction purpose are not explicitly encoded in COCO-17. The natural first question is whether a proposed target is identifiable from the available representation and annotation, before choosing a larger architecture. This follows from the representation inventory above, not a claim of a new experimental result. [ASDMotion, joint definitions](../external/ASDMotion-main/src/asdmotion/pipeline/skeleton_layout.py).

## 3. Annotated release does not directly match the fork input

The annotated-release audit observed records with `keypoint: [T,17,2]`, `keypoint_score: [T,17]`, `binary_label`, `action_name`, `identifier`, `fps`, `total_frames`, `start_frame`, and `end_frame`. This differs from the continuous archive's `[1,T,17,2]` representation. The fork loader expects sample `label`, `frame_dir` or `filename`, and (when `split` is supplied) an outer `{'split': ..., 'annotations': [...]}` container. Its configured `ChildDetect` additionally expects `[M,T,17,2]` and `child_ids`. [Annotated schema](../data/processed/dataset_structure.json); [continuous archive schema](../data/processed/archive_summary.json); [MMAction fork, `pose_dataset.py:98–113`](../references/source_snapshots/mmaction_pose_dataset.py); [`pose_loading.py:699–707`](../references/source_snapshots/mmaction_pose_loading.py).

**Proposed adapter contract, not proof of recovered paper preprocessing:** validate dimensions; add a singleton person axis for already-selected child poses; map `binary_label` to integer `label` only after verifying label semantics; use a unique stable `identifier` as `frame_dir`; retain provenance separately; remove `ChildDetect` when selection has already occurred; preserve subject-grouped split membership from verified metadata. Do not infer identity/group membership solely from an identifier prefix until the data dictionary is verified. Verify image shape is `(height,width)` before passing it to MMAction. These are requirements inferred from the loader and transforms, not modifications made to upstream. [MMAction fork, `pose_dataset.py:98–113`](../references/source_snapshots/mmaction_pose_dataset.py); [`pose_loading.py:591,699–707`](../references/source_snapshots/mmaction_pose_loading.py).

The config uses cross-entropy weights `[0.75,0.25]`, while inference selects score column 1 as SMM. **If the training labels also use 1=SMM**, positive examples receive one third the negative-example loss weight. This is not inverse-frequency minority balancing. The original training-label convention must therefore be confirmed; changing weights would be an explicit new experiment rather than exact reproduction. [MMAction fork, `asdmotion.py:18–26`](../references/source_snapshots/mmaction_asdmotion.py); [ASDMotion, `detector.py:49–50`](../external/ASDMotion-main/src/asdmotion/detector/detector.py).

**Additional measured schema cautions:** annotated-release split keys are `train`/`test`, not the fork's `train0`/`test0`; frame rates include both 25 and 30 fps; two duplicated identifiers were found; the 329 first identifier-token groups differ from the paper's 241 children. These prohibit silently treating identifier prefixes as participant IDs. One observed record has `start_frame=649`, `end_frame=654`, but 211 pose frames at 30 fps: the endpoint difference is not its pose-frame count. Endpoint units and trimming/alignment history remain unresolved. Adaptation must retain original fields and explicitly flag the mismatch rather than silently reinterpret it. [Annotated schema](../data/processed/dataset_structure.json); [full annotated summary](../data/processed/dataset_summary.json); [released-split audit](../data/processed/released_split_audit.json). The continuous archive separately supplies explicit child and assessment identities in `db.csv`; a crosswalk from labeled identifiers to these identities has **not** been verified. [Extracted archive manifest](../data/interim/archive_metadata.csv).

## 4. Confirmed source defects and executable counterexamples

All line numbers below refer to the pinned snapshots. The 10-test suite executes AST-extracted upstream functions, with lightweight dependency substitutes; no CUDA inference was performed. [Local tests](../tests/test_upstream_semantics.py).

| Finding | Evidence and concrete consequence | Classification |
|---|---|---|
| Undefined `NET_NAME` | `aggregator.py:62` references a name never defined/imported. One nonempty score row raises `NameError`. | Confirmed, tested runtime blocker |
| Missing `adjust` key | `prepare_skeleton` constructs dictionary at `openpose_executor.py:105–113` without `adjust`; `to_poseC3D:196` unconditionally reads it. Fresh generated input fails with `KeyError`. | Confirmed, tested converter blocker |
| Optional child detection is not operational on fresh paths | `preprocess.py:58–64` sets every ID to -1 when disabled, then immediately raises because all are -1. Existing cached skeleton may bypass this branch. | Confirmed source contradiction |
| Final positive run is not merged | `unify`, `aggregator.py:20`, tests `j < n-1`. Test supplies `NET_NAME` locally solely to reach this downstream logic. | Confirmed, tested event/duration defect |
| Threshold equality differs from paper | Code `score > threshold` (`aggregator.py:44`); paper uses `>=0.85` (p.4). A score exactly .85 is negative in source. | Confirmed, tested semantic difference |
| Invalid ID silently chooses a real slot | Fork `ChildDetect`, `pose_loading.py:705–706`, uses negative NumPy indexing; child ID -1 selects last person rather than explicitly marking missing. ## 5. Additional reproducibility risks, not demonstrated dataset failures

- **Ordering:** `openpose_to_json` iterates unsorted `os.listdir` then assigns frame index by enumeration (`openpose_executor.py:126,136,146`). If directory order differs from temporal order, motion and child alignment can be corrupted. No claim that the published dataset is actually scrambled. [ASDMotion, extraction source](../external/ASDMotion-main/src/asdmotion/pipeline/openpose_executor.py).
- **Image-size convention:** video properties are `(width,height)` in `utils.py:46,51,65`, passed unchanged as `img_shape` at `openpose_executor.py:191`; fork consumes `(height,width)` at `pose_loading.py:591`. This is a confirmed interface mismatch for fresh extraction, whose practical effect depends on subsequent PoseCompact cropping and input data. Do not assume archived records share it. [ASDMotion utilities](../external/ASDMotion-main/src/asdmotion/utils.py); [converter](../external/ASDMotion-main/src/asdmotion/pipeline/openpose_executor.py); [fork](../references/source_snapshots/mmaction_pose_loading.py).
- **Length mismatch tolerance:** matcher accepts detection/pose frame-count differences up to tolerance but the reconciliation code is commented out (`skeleton_matcher.py:82–99`). Extra detections can overrun pose arrays; fewer leave missing IDs. [ASDMotion matcher](../external/ASDMotion-main/src/asdmotion/child_detector/skeleton_matcher.py).
- **Environment:** `requirements.txt` includes many author-machine `file:///...` artifacts; README lists torch 1.13 but requirements pin torch 2.2.1; fork sampling calls removed `np.int` (`pose_loading.py:127`); inference shell script hard-codes `C:\Users\owner\...`, while Predictor stores but does not use configured `mmlab_python`. These require a documented compatibility environment or explicit patch set. [Requirements](../external/ASDMotion-main/requirements.txt); [README:23–28](../external/ASDMotion-main/README.md); [fork sampler](../references/source_snapshots/mmaction_pose_loading.py); [batch script](../external/ASDMotion-main/resources/run_in_env.bat); [Predictor:24,32–37](../external/ASDMotion-main/src/asdmotion/detector/detector.py).
- **Cache identity:** outputs are reused by file existence, without comparison of source content, config, or checkpoint hash (`preprocess.py:33–54`, `detector.py:30,61–65`). Changed experiments can read stale intermediates. [Preprocessing](../external/ASDMotion-main/src/asdmotion/detector/preprocess.py); [inference](../external/ASDMotion-main/src/asdmotion/detector/detector.py).
- **Validation is named test:** fork config uses `test0` for both validation and test. This is a leakage risk if used for model/threshold selection, not proof the paper selected on test. Recover actual execution logs and original split protocol. [Fork config](../references/source_snapshots/mmaction_asdmotion.py).

## 6. Reproduction decisions and research implications

**Proposed work sequence:** first make a validated, deterministic released-record adapter and preserve the original archive; next implement the paper's frame-wise maximum/threshold/union as a separate reference evaluator; test empty recordings, tail windows, missing identity, zero-valid-duration, overlapping events, and equality thresholds; only then train a small baseline and the PoseC3D baseline under subject-disjoint splits. Keep patched and faithful-as-released pipelines separately named. This sequence is our research recommendation motivated by the confirmed defects, not a claim about the authors' private code. [Counterexample suite](../tests/test_upstream_semantics.py).

**Proposed initial research questions:** (1) does explicit missing-pose masking improve generalization at matched coverage; (2) how much apparent accuracy comes from event-length/context rather than stereotypical kinematics; (3) do temporal localization and per-child duration calibration improve beyond clip classification; (4) does camera/assessment context change reliability? These are hypotheses requiring experiments and metadata. They follow from source representation and summary limitations and should not be advertised as established findings. [Pipeline inventory and counterexamples above]; [Barami (2024/09), limitations p.9](../references/papers/Barami2024_JAMA.pdf).
